  - 数据处理状态
  - 训练记录状态
  - 模型版本数量
  - 评估任务空态/结果态

#### 主流程 2：平台资源配置闭环
- 起点：系统管理
- 步骤 1：创建或选择项目
- 步骤 2：导入/管理 Kubernetes 集群
- 步骤 3：绑定存储配置
- 步骤 4：绑定镜像仓库与镜像
- 步骤 5：管理基础模型和平台成员

  - 集群连接是否正常
  - 存储是否联通
  - 镜像和基础模型是否可用
- 关键反馈点：
  - 连接测试结果
  - 绑定成功与否
  - 资源运行状态

#### 主流程 3：生产环境异常流
- 起点：进入菜单或创建入口
- 步骤 1：访问某些父路由或创建页
- 步骤 2：直接看到 404 或 `common.notFound`
- 终点：用户无法继续流程
- 关键判断点：页面是否已实现、是否有上下文前提、是否只是错误截图
- 关键反馈点：404 页面、告警横幅

## H. 开发计划

### H.1 本轮建议优先级
1. 数据服务标准链路与数据处理闭环
2. 模型管理与评估闭环
3. 系统管理的最小可运行资源后端

### H.2 本轮计划处理内容
- 前端：
  - 第一阶段不动受保护的大模型训练页面
  - 先收敛首页与信息架构认知
  - 优先把数据管理、数据标注、数据清洗、评估列表/空态、模型管理对齐生产环境
- 后端：
  - 先建立最小后端能力骨架或前后端边界层
  - 定义数据集、任务、模型、评估、项目、资源实体与状态流转
- 接口：
  - 先补列表、详情、创建、删除、启动/执行类接口契约
  - 对训练模块只建立周边接口契约，不改训练前端
- 数据结构：
  - 统一 Dataset / DatasetVersion / Task / Model / EvaluationTask / Project / Cluster 等实体
- 联调：
  - 先完成数据服务 -> 训练引用 -> 模型 -> 评估的最小闭环
- PRD / RPD 同步：
  - 同步修正首页、评估创建、机器学习、非标准功能的文档理解
- 页面内嵌设计文档：
  - 后续每进入一个页面开发，就同步更新该页面侧板文档内容
- 验证：
  - 每一阶段做路由、列表、创建、详情、删除、状态流转、设计文档侧板交互自检

### H.3 分阶段开发计划

#### 阶段 0：基线治理
- 目标：
  - 固化生产环境拆解结果
  - 建立统一接口抽象和后端占位层
  - 明确受保护模块和非标准功能隔离策略
- 产出：
  - 统一 API/仓储边界
  - 页面文档映射清单
  - 非标准入口隐藏或降级方案

#### 阶段 1：数据服务标准闭环
- 目标：
  - 对齐训练数据管理、测试数据管理、推理结果集、数据标注、数据清洗
  - 让它们具备真实数据对象和状态流转
- 原因：
  - 这是训练与评估的上游必经链路
  - 不会误伤受保护的大模型训练主页面

#### 阶段 2：模型管理与评估闭环
- 目标：
  - 训练产物进入模型管理
  - 评估任务可真实消费模型与数据
  - 评估列表、状态和结果对齐生产环境
- 原因：
  - 形成“数据 -> 训练 -> 模型 -> 评估”的业务闭环

#### 阶段 3：系统管理最小可运行支撑
- 目标：
  - 打通项目、集群、存储、镜像、基础模型、平台管理员的核心数据结构和接口
  - 满足可运行、可构建、可部署的基础平台要求
- 原因：
  - 这是网站系统部署和真实业务运行的前置条件

#### 阶段 4：首页与壳层校正
- 目标：
  - 将首页从当前仪表盘式实现校正到生产环境欢迎页语义
  - 补齐设计文档内容覆盖率
  - 对菜单和入口做范围治理
- 原因：
  - 首页差异很大，但不是主流程最先阻塞点，因此放在数据主链路后处理更稳妥

#### 阶段 5：延后核验模块
- 范围：
  - 模型服务
  - 机器学习
  - 镜像仓库单页
- 策略：
  - 二次核验生产环境后再决定是保留、降级还是隐藏

### H.4 暂不处理内容
- 不修改“模型训练 - 大模型训练”页面结构、交互、路由和数据结构
- 不扩展业务测试数据集、业务推理结果集、文件管理、业务效果评估、API 服务
- 不优先开发机器学习模块
- 不做与目标无关的大规模重构
