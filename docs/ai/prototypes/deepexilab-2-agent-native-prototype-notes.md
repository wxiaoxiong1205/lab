# DeepexiLab 2.0 Agent Native 原型说明

> 原型文件：`deepexilab-2-agent-native-prototype.html`  
> 原型版本：v1.0  
> 更新时间：2026-06-18  
> 原型性质：throwaway UI prototype，仅用于评审信息架构、入口路径、页面形态和关键交互，不作为正式实现代码。

## 一、本版重构目标

本版按照“生产级主闭环”重构，不再把 2.0 原型做成页面集合，而是验证以下完整路径：

```text
1.0 平台业务对象
  -> 右上角唯一 Lab Agent 入口
  -> Lab Agent Workspace
  -> 目标型 Agent 工作
  -> 实验报告生成或更新
  -> 数据报告详情 / 实验对比详情 / 实验日志详情
  -> SkillHub 能力包 / MCP 连接治理边界
```

本版重点解决上一版仍不够生产化的问题：

- 旧原型像页面拼装，缺少从目标到报告再到证据的主闭环。
- 实验报告阅读体验不够像正式成果文档。
- 数据报告、实验对比、实验日志没有充分体现“证据资产”定位。
- 实验对比缺少图表化表达。
- SkillHub 仍偏底层 Skill 平铺，不符合“能力包”产品口径。
- 系统接入边界曾在产品页面中暴露过多，需要收回到文档和实现层。

## 二、本版关键变化

### 2.1 平台基础页

- 按用户截图回收为 DeepexiLab 1.0 任务概览壳层：顶部包含 Deepexi / LAB / 项目选择 / 任务概览、数据服务、模型训练、模型评估、模型服务等导航，左侧只有任务概览。
- 右上角只保留一个 `Lab Agent` 入口，文案不使用“打开”。
- 平台页不展示 `MCP 状态`、`查看实验报告`、`用 Agent 分析`、`查看对比资产`、`诊断日志` 等 2.0 功能入口。
- MCP、实验报告、实验对比、日志详情等能力只在进入 Lab Agent Workspace 后展示。

### 2.2 Lab Agent Workspace

- 新对话页改为 Codex 式空白输入态：主区聚焦输入框和少量快捷能力。
- 左侧参考 Codex 的组织方式：新对话、已保存对话列表，再到实验档案和插件与工具；不展示项目概念。
- 对话详情改为常规消息流，报告生成结果作为对话中的一个结果附件呈现，不再做成报告页式内容区。
- 点击对话列表进入对话线程，不再误跳实验报告列表。
- 右侧对话抽屉默认收起，通过右上角图标式按钮展开，不使用显性的 `Agent` 文案按钮。

### 2.3 实验报告

- 实验报告列表先行，支持目标型命名、可靠性状态、版本、来源和引用对象。
- 实验报告列表增加“进行中”状态样例，用于表达报告完全生成前的过程观察入口。
- 报告详情改为正式文档阅读形态。
- 进行中的报告详情顶部增加实时观察区，展示当前阶段、当前进度、预计进度、ETA、指标走势、阶段时间线、最近事件和关键风险。
- 报告详情包含：原始需求 / 实验目标、报告变更记录、实验结论与总结、实验路径、关键证据摘要、风险与证据不足、下一步动作、证据与引用。
- 证据导航从报告跳转到数据报告详情、实验对比详情、实验日志详情。
- 实验完成后，实时观察区收敛为“执行过程”和“关键证据摘要”；原始曲线和事件保留为证据资产或事实层记录。

### 2.4 三类证据资产

- 数据报告详情：突出处理前后样本、重复样本、困难样本变化、适用目标和数据风险。
- 实验对比详情：补充核心指标柱状图、训练/评估曲线折线图、能力维度涨跌图和对比矩阵。
- 实验日志详情：改为完整日志查看器，支持异常高亮、行号、来源追溯和引用关系。

### 2.5 SkillHub / MCP

- SkillHub 展示系统能力包和我的 Skill，不再平铺内部 Skills，也不展示能力包内部编排过程。
- 系统能力包包括：报告生成、实验对比、数据分析、日志与报错诊断、代码与参数检查等。
- MCP 页面只展示用户可理解的系统 MCP、我的 MCP、连接状态和授权范围。
- Lab CLI、Lab MCP Server、Context Pack 等系统接入细节不作为用户产品页面显性内容。

## 三、推荐评审路径

1. 打开原型默认页，先看 DeepexiLab 1.0 任务概览页是否贴近当前产品截图。
2. 确认平台页只有右上角一个 `Lab Agent` 入口。
3. 点击右上角 `Lab Agent`，进入 Workspace 新对话，确认界面是空白输入态。
4. 点击左侧某条已保存对话，查看常规消息流、报告生成结果附件和撤回入口。
5. 从对话结果卡片点击“查看报告”，进入实验报告详情。
6. 检查进行中报告是否能展示实时指标走势、当前进度、预计进度、ETA、阶段时间线、最近事件和关键风险。
7. 检查报告是否具备正式成果文档的阅读层级。
8. 从报告右侧证据导航进入数据报告详情，确认数据证据页定位。
9. 进入实验对比详情，确认柱状图、折线图、能力涨跌图和矩阵是否足够表达对比。
10. 进入实验日志详情，确认完整日志、异常高亮和来源追溯是否清楚。
11. 进入 SkillHub，确认系统能力包表达是否符合产品口径。
12. 进入 MCP，确认页面只展示连接和授权状态，不出现 CLI 命令、内部协议或系统接入架构。
13. 点击右上角图标式展开按钮，确认对话抽屉默认收起、按需展开、追问不自动写回报告。

## 四、当前原型路由

原型通过 URL 参数切换页面：

| 路由 | 页面 |
| --- | --- |
| `?route=platform` | 1.0 平台基础页 |
| `?route=chat` | Workspace 新对话 |
| `?route=reports` | 实验报告列表 |
| `?route=report-detail` | 实验报告详情，默认展示进行中实时观察区 |
| `?route=data` | 数据报告详情列表 |
| `?route=data-detail` | 数据报告详情 |
| `?route=compare` | 实验对比详情列表 |
| `?route=compare-detail` | 实验对比详情 |
| `?route=logs` | 实验日志详情列表 |
| `?route=log-detail` | 实验日志详情 |
| `?route=skillhub` | SkillHub |
| `?route=mcp` | MCP |

附加参数：

- `agent=open`：展开右侧 Agent 抽屉。
- `tab=system`：查看系统能力包或系统 MCP。
- `tab=mine`：查看我的 Skill 或我的 MCP。

## 五、评审重点

本原型应重点验证：

- 2.0 是否清楚建立在 1.0 平台业务对象之上，且平台页只出现右上角唯一 `Lab Agent` 入口。
- 用户是否能理解“目标型 Agent 工作 -> 实验报告 -> 证据资产”的闭环。
- 实验报告是否像正式成果，而不是摘要卡片集合。
- 算法工程师是否能理解“报告未完成前先观察过程，完成后再沉淀正式结论”的状态变化。
- 数据报告、实验对比、实验日志是否承担证据页职责。
- SkillHub 能力包是否比底层 Skills 平铺更易理解。
- 系统接入能力是否在产品界面中被隐藏到合适程度，只保留用户需要管理的 MCP 连接状态。
- Agent 抽屉是否足够克制，不打断报告阅读。
- 平台原生业务操作与 Agent 目标型报告沉淀边界是否清楚。

## 六、暂不验证的内容

本原型不验证：

- 真实接口与数据模型。
- 真实 Skill 执行。
- MCP 连接协议。
- CLI 安装流程。
- 权限校验实现。
- 真实报告生成算法。
- 真实 PDF/Markdown 导出。

这些内容应在设计方案确认后，进入独立的前后端开发方案和接口方案阶段。

## 七、仍需评审确认

- 实验报告详情是否需要固定右侧目录，还是保持当前证据导航。
- 新对话页和对话线程的信息密度是否足够贴近 Codex。
- MCP 页面是否还需要进一步弱化系统连接，只保留我的 MCP。
- 结构化配置草案是否需要在原型中展开为完整表单。
- 报告协作评论、项目级 Skill/MCP、公开分享是否进入 P1/P2，而不是 P0。
