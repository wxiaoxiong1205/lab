# 下一阶段模块开发计划

## 1. 当前对系统的理解
- 生产环境的标准主线已经比较明确：
  - 数据管理
  - 模型训练
  - 模型评估
  - 模型服务
  - 系统管理
  - 平台管理员
- 当前仓库已经完成了数据服务模块的多轮对齐，沉淀了：
  - 生产环境拆解方法
  - 路由先对齐、页面后对齐的执行顺序
  - 共享数据源
  - API 契约层
  - 最小本地后端
  - 统一任务状态流转规则的起步实现

## 2. 数据服务模块开发经验总结

### 2.1 有效做法
- 先拆生产环境，再写页面
  - 先确认真实路由、列表列、详情结构、动作入口和异常流，再动代码。
- 先收主链路，不碰已明确排除项
  - 数据服务阶段只处理训练数据、测试数据、推理结果、数据标注、数据清洗。
- 路由先对齐，页面形态后对齐
  - 先把真实路径补起来，再把弹层逐步推进成整页。
- 详情页围绕“对象 + 版本 + 当前版本明细”设计
  - 训练数据和测试数据都验证了这一点。
- 新增版本必须支持继承上一版本数据
  - 否则版本系统只是视觉假象。
- 页面之间必须共享同一数据源
  - 数据标注、数据清洗、推理结果都会消费数据集，不能各自维护孤立 mock。
- 共享 store 之后必须再抽 API 层
  - 页面直接依赖 store actions 很快会卡住。
- 搜索、筛选、分页都要下沉到统一查询层
  - 页面内自己 `filter` 只能做短期原型，不适合继续扩展。
- 任务型模块要尽早统一状态机
  - 推理结果、清洗任务这类页面的核心在状态流转和操作约束。
- 页面内嵌设计文档要和页面一起演进
  - 否则右侧文档会很快失真。

### 2.2 已踩过的坑
- 只改视觉不改路由，后面返工成本高。
- 只做页面不做共享数据层，跨页面联动会越来越碎。
- 只做共享数据层不抽 API 层，后续接后端仍然会痛。
- 详情页如果不做版本切换，训练/测试数据模块很难和生产环境一致。
- 任务状态如果只写在单页里，后续其它模块很容易重复实现且互相冲突。

### 2.3 可复用资产
- 通用方法：
  - 生产环境拆解 -> 差异清单 -> 路由对齐 -> 页面结构对齐 -> 数据层对齐 -> 状态机对齐
- 已可复用的代码层资产：
  - 数据服务 API 层与最小后端模式
  - 列表查询/分页模式
  - 详情页“左侧版本 + 右侧信息/明细”结构
  - 任务状态流转 helper 雏形

## 3. 后续统一状态流转规则

> 以下规则后续优先作为任务型模块的统一基线：

- 已创建：启动、编辑、查看详情、删除
- 定时待启动：编辑、查看详情、删除
- 启动中：查看详情
- 排队中：终止、查看详情
- 运行中：终止、查看详情
- 已完成：查看详情、删除
- 失败：重新提交、查看详情、删除
- 已终止：重新提交、查看详情、删除

补充规则：
- 启动中的任务不支持终止
- 点击终止时提示：`正在启动中任务不支持终止`

优先适用模块：
- 推理结果集
- 大模型训练之外的任务型模块
- 自动评估
- 基准评估
- 数据清洗
- 模型管理中的异步操作
- 基础模型管理中的运行任务
- 模型部署 / 在线推理服务

## 5. 推荐开发顺序

### 5.1 第一优先
- 在线Notebook
- 模型管理
- 效果评估
- 模型部署

原因：
- 和数据服务主链路耦合最强
- 可直接复用数据服务已沉淀的模式
- 不会误伤受保护的大模型训练主链路

### 5.2 第二优先
- 评估指标
- 在线推理服务
- 项目管理
- 集群管理
- 存储管理

原因：
- 这些模块要么承接训练/评估产物，要么作为平台支撑层

### 5.3 第三优先
- 镜像管理
- 基础模型管理
- 系统配置
- 平台管理员

### 5.4 最后处理
- 机器学习整组模块

原因：
- 仓库内历史资料显示该模块在生产环境中存在 404 / 不稳定入口风险
- 适合在前两波完成后，再做专项复核和分步推进

## 6. 并行协作建议

### 6.1 推荐的子 Agent 分工
- Agent A：模型训练簇
  - 在线Notebook
  - 模型管理
  - 明确排除受保护的大模型训练主链路

- Agent B：评估 + 模型服务簇
  - 效果评估
  - 评估指标
  - 模型部署
  - 在线推理服务

- Agent C：系统管理 + 平台管理员簇
  - 项目管理
  - 集群管理
  - 存储管理
  - 镜像管理
  - 基础模型管理
  - 系统配置
  - 平台管理员

- Agent D：机器学习簇
  - 先做生产环境稳定性复核
  - 再决定哪些页面正式进入开发

### 6.2 并行协作规则
- 按模块簇拆，不按单页随意拆
- 每个 Agent 先拆生产环境，再看代码
- 每个 Agent 输出：
  - 当前实现现状
  - 生产环境真实表现
  - 差异清单
  - 依赖实体
  - 开发顺序建议
- 若上游子 Agent 不稳定，不作为主线阻塞条件

## 7. 生产环境核对要求
- 接下来每个模块开工前，仍然必须重新核对生产环境
- 核对优先内容：

  - 创建页与详情页结构
  - 状态流转
  - 按钮显隐逻辑

## 8. 风险点
- 子 Agent 当前偶发 502，不稳定，不能作为唯一分析来源
- 机器学习模块在生产资料中稳定性较差，优先级不应高于主线
- 受保护模块“大模型训练”必须持续绕开
- 多模块并行后，页面内嵌设计文档更容易滞后，必须同步维护
