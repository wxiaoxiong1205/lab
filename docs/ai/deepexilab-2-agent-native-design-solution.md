# DeepexiLab 2.0 Agent Native 生产级设计方案

> 文档版本：v1.0  
> 更新日期：2026-06-18  
> 当前基线：第二阶段用户确认的 2.0 Agent Native 方向  
> 输入依据：`deepexilab-2-agent-native-rpd.md`、`deepexilab-2-agent-native-requirement-exploration.md`、`deepexilab-2-agent-native-system-skills.md`、问卷调研结论、现有 DeepexiLab 1.0 平台基线  
> 文档定位：用于产品、设计、研发、算法、测试、交付进行 2.0 设计评审；不替代后续前后端开发方案。

## 一、生产级设计结论

DeepexiLab 2.0 的设计目标不是给平台增加一个聊天窗口，也不是新建一个脱离业务对象的报告中心，而是把 DeepexiLab 升级为 **Agent Native 模型研发工作台**。

生产级方案必须回答五个问题：

1. 用户从现有 1.0 平台如何进入 Agent Native 工作台。
2. Agent 如何判断一次工作是否应生成或更新实验报告。
3. 实验报告如何成为目标型工作的统一回看入口。
4. 数据、对比、日志等细节如何作为证据资产支撑报告，而不是抢占报告主位置。
5. Notebook、SSH、IDE 等外部工作场景如何在系统层受控回流到平台，但不在普通产品界面中暴露中间产物。

本版设计采用以下主闭环：

```text
1.0 平台业务对象
  -> 平台右上角唯一 Lab Agent 入口
  -> Lab Agent Workspace
  -> 目标型 Agent 工作
  -> 生成或更新实验报告
  -> 报告未完成前展示实时观察区
  -> 引用数据报告详情 / 实验对比详情 / 实验日志详情
  -> 用户在对话卡片、报告详情、外部返回链接中回看与纠正
```

设计上的核心变化：

- 从“页面集合”改为“目标型工作闭环”。
- 从“报告页面”改为“正式实验成果文档”。
- 从“详情页堆内容”改为“证据资产页”。
- 从“零散 Skill 列表”改为“用户可理解的系统能力包”。
- 从“系统接入能力外露”改为“产品界面只呈现用户可理解的连接和授权状态”。

## 二、产品对象与边界

### 2.1 对象边界

| 对象 | 生产定位 | 不做什么 |
| --- | --- | --- |
| 平台业务对象 | 数据集、训练任务、评估任务、模型、服务、文件、Notebook 等事实对象的主位置。 | 不迁移到实验档案，不因 Agent 出现而失去原模块入口。 |
| Lab Agent Workspace | 2.0 的统一 Agent 工作区，承接对话、实验档案、SkillHub、MCP。 | 不做营销首页，不把每个业务模块重做一遍。 |
| 实验报告 | Agent 目标型工作的统一正式成果，按目标聚合过程、结论、证据和下一步。 | 不按“数据处理/日志分析/报错诊断”拆成多个主报告。 |
| 数据报告详情 | 数据处理、数据对比、数据适用性分析的证据资产。 | 不替代数据服务，不展示完整数据集管理能力。 |
| 实验对比详情 | 多训练、多评估、多版本、多数据之间的结构化对比证据资产。 | 不做 BI 大屏，不成为新的训练任务列表。 |
| 实验日志详情 | 日志原文、异常片段、来源路径、采集方式和引用关系的追溯资产。 | 不把日志分析结论从实验报告中拆走。 |
| SkillHub | Agent 能力包目录，展示系统能力包和用户个人能力包。 | 不做报告模板配置中心，不平铺全部内部 Skills。 |
| MCP | 系统 MCP 与我的 MCP 的连接目录。 | 不展示完整审计中心，不允许绕过权限。 |

### 2.2 报告生成边界

生成或更新实验报告的条件：

- 有明确原始目标或可推断目标。
- Agent 或受控系统连接围绕目标产出分析、处理、诊断、对比、复盘或交付结论。
- 工作结果需要被后续回看、引用、导出或交付。

不生成实验报告的情况：

- 用户只手动上传数据、创建训练任务、启动评估、部署服务。
- 用户只是查询状态、询问页面位置、查看参数。
- 平台原生业务对象已经能完整承接结果，且没有目标型分析产出。

用户必须知道报告发生变化。生成或更新后，当前对话插入结果附件，提供查看、撤回本次追加、补证重新生成等操作。

## 三、信息架构与入口路径

### 3.1 Workspace 左侧结构

```text
Lab Agent Workspace
├─ 新对话
├─ 对话列表
├─ 实验档案
│  ├─ 实验报告
│  ├─ 数据报告详情
│  ├─ 实验对比详情
│  └─ 实验日志详情
└─ 插件与工具
   ├─ SkillHub
   └─ MCP
```

设计规则：

- 左侧参考 Codex 的组织方式：先给出新对话入口，再展示已保存对话列表。
- `对话` 不指向实验报告列表；点击某条对话进入该对话线程。
- 左侧只展开对话，不展开具体报告和详情资产。
- 点击资产类型后，主内容区先展示列表，再进入详情。
- 报告、数据报告、对比、日志都支持搜索、筛选、状态、来源、创建人和时间字段。
- 数据处理与分析不是独立左侧模块，它由数据分析能力包、数据报告详情和实验报告共同承接。

### 3.2 入口路径

| 来源 | 默认落点 | 关键行为 |
| --- | --- | --- |
| 平台右上角 Lab Agent 入口 | 新对话 | 平台内唯一入口，文字为 `Lab Agent`，不使用“打开”。 |
| 对话结果附件 | 对应实验报告或详情资产 | 用户明确看到报告生成/更新结果。 |
| 实验报告链接 | 实验报告详情 | 默认右侧 Agent 收起，保证阅读优先。 |
| 数据报告/对比/日志链接 | 对应详情资产 | 顶部显示来源报告、来源渠道和引用关系。 |
| Notebook/IDE 等外部场景返回链接 | 对应资产详情 | 直达资产，不要求用户先理解平台导航。 |

### 3.3 壳层布局

```text
┌──────────────────────────────────────────────────────────────────┐
│ 顶部栏：Workspace 标识 / 搜索 / 图标式对话展开 / 用户信息           │
├───────────────┬──────────────────────────────────────┬───────────┤
│ 左侧导航       │ 主内容区                              │ Agent 抽屉 │
│ 新对话         │ 对话、列表、详情、报告、配置、确认面板 │ 默认收起    │
│ 对话           │                                      │ 按需展开    │
│ 实验档案       │                                      │            │
│ 插件与工具     │                                      │            │
└───────────────┴──────────────────────────────────────┴───────────┘
```

布局要求：

- 桌面优先，左侧 220-248px，Agent 抽屉 360-420px。
- 详情页默认不展示右侧对话，只保留右上角类似 Codex 的图标式展开按钮，不使用显性 `Agent` 文案按钮。
- 抽屉展开后带入当前资产上下文，但追问不自动写回报告。
- 窄屏下左侧与 Agent 抽屉均改为覆盖式面板。

## 四、核心页面设计

### 4.1 1.0 平台基础页与 2.0 入口

定位：让 2.0 从现有 DeepexiLab 业务平台自然进入，而不是凭空出现一个新系统。

页面表现：

- 平台基础页必须贴近当前 1.0 产品样式：顶部包含 Deepexi / LAB / 项目选择 / 任务概览、数据服务、模型训练、模型评估、模型服务等业务域导航；左侧按当前页面模块展示，不新增 2.0 专属导航分组。
- 2.0 在平台内只保留右上角唯一 `Lab Agent` 入口，不使用“打开 Lab Agent”文案。
- 平台页面内不展示 `MCP 状态`、`查看实验报告`、`用 Agent 分析`、`查看对比资产`、`诊断日志` 等 2.0 功能入口。
- MCP、实验报告、实验对比、日志详情等能力均进入 Lab Agent Workspace 后展示。
- 平台原生按钮不会自动生成实验报告，只有用户从右上角 `Lab Agent` 进入并发起目标型工作后才可能沉淀报告。

生产验收点：

- 用户看到的是当前平台样式，而不是一套新画的壳层。
- 业务对象仍然有清楚归属。
- 平台页只出现一个右上角 `Lab Agent` 入口，入口不会散落到侧栏、表格、页面操作区或 MCP 状态中。

### 4.2 新对话页

定位：目标型 Agent 工作的起点。

页面结构：

- 对话主区：用户消息、Agent 回复、报告生成/更新结果附件、动作确认卡片。
- 底部输入区：输入框、上下文附加、常用能力入口。

常用能力入口：

- 对比实验。
- 分析日志。
- 诊断报错。
- 生成报告。
- 处理数据。
- 生成交付材料。

结果卡片字段：

| 字段 | 说明 |
| --- | --- |
| 产物类型 | 实验报告、数据报告详情、实验对比详情、实验日志详情、动作确认。 |
| 名称 | 按目标命名，例如“DPO 参数调优实验”。 |
| 可靠性状态 | 可信、有风险、证据不足、人工修订、生成失败。 |
| 主要结论 | 一句话说明本次产物为什么值得查看。 |
| 引用的任务/数据 | 训练任务、评估任务、数据版本、日志来源、Notebook 会话等。 |
| 操作 | 查看、撤回本次追加、补充证据并重新生成。 |

### 4.3 实验报告列表

定位：目标型工作成果的统一查找入口。

列表字段：

- 报告名称。
- 主要结论。
- 可靠性状态。
- 创建人。
- 最新版本。
- 最新更新时间。
- 来源渠道。
- 引用的任务/数据。
- 是否有待补证项。

筛选项：

- 关键词。
- 创建人。
- 可靠性状态。
- 来源渠道。
- 时间范围。
- 引用对象类型。

空状态：

> 通过 Lab Agent 或受控系统连接发起目标型工作后，实验报告会在这里沉淀。普通平台操作仍保留在原业务模块中。

### 4.4 实验报告详情

定位：一次目标型工作的正式成果文档。

进行中定位：实验报告完全生成前，报告详情先作为“同一目标的过程观察入口”，展示实时指标走势、当前进程、预计进程、关键风险和已采集证据；完成后再收敛为正式成果文档。

报告头部：

- 报告名称。
- 生命周期状态和可靠性状态。
- 当前版本。
- 最新更新时间。
- 创建人。
- 来源渠道。
- 操作：编辑、导出、历史版本、补充证据并重新生成。

进行中报告头部补充：

- 当前阶段：数据读取、训练中、评估中、日志分析中、报告生成中等。
- 当前进度：平台事实层返回的真实完成百分比。
- 预计进度：按平台 ETA、阶段权重或历史耗时估算的预计完成百分比。
- ETA：预计剩余时间和预计完成时间。
- 关键风险：指标异常、日志缺段、评估失败、进度滞后、证据缺失。
- 数据更新时间：显示最近一次运行快照更新时间；轮询失败时保留最近快照并提示异常。

报告正文前置实时观察区：

| 模块 | 设计要求 |
| --- | --- |
| 进程对比 | 并列展示当前进度和预计进度，明显滞后时用文字风险提示，不只依赖颜色。 |
| 核心指标走势 | 使用折线图展示已采集到的 loss、eval loss、win-rate、accuracy、F1、stability 等指标；缺失指标显示暂无数据。 |
| 阶段时间线 | 展示已完成、进行中、待开始、异常阻塞阶段。 |
| 最近事件 | 展示训练、评估、Notebook、CLI/MCP、Agent Bridge 回流的关键事件。 |
| 关键风险 | 汇总指标异常、日志缺段、评估失败、进度滞后、证据缺失。 |

报告正文固定模块：

| 模块 | 设计要求 |
| --- | --- |
| 原始需求 / 实验目标 | 位于报告前部，必须清楚说明工作为什么发生。 |
| 报告变更记录 | 展示当前版本相较上一版本的新增、补证、修订或人工修改。 |
| 实验结论与总结 | 最核心结论、风险、是否建议交付或继续投入。 |
| 实验路径 / 执行过程 | 说明从目标、方案、执行、异常、修复到结论的过程。 |
| 关键证据摘要 | 只放最能支撑结论的摘要，并跳转详情资产或原业务对象。 |
| 风险与证据不足 | 明确缺哪些日志、指标、参数、数据版本或评估口径。 |
| 下一步动作 | 给出继续实验、补证、停止投入、进入交付或回滚等建议。 |
| 证据与引用 | 弱展示任务、数据、日志、Skill/MCP、外部会话等引用。 |

按需模块：

- 实验成败归因。
- 超参数敏感性。
- 数据贡献分析。
- 训练曲线诊断。
- 评测一致性与回归分析。
- 成本收益分析。
- 可复现性检查。
- 代码/参数检查。
- 日志分析摘要。
- 报错诊断与修复记录。
- 研究叙事总结。

完成后的处理规则：

- 实时观察区不单独作为结论区保留，收敛为“实验路径 / 执行过程”和“关键证据摘要”。
- 原始曲线、最近事件和运行快照保留为事实层记录或证据资产，可从报告跳转查看。
- 正式结论仍由报告生成能力组织，过程走势不能直接替代最终结论。

详情页右侧可以提供“证据导航”，但不做复杂分栏正文。正文保持连续阅读，方便导出和评审。

首版接口策略：

- 前端读取 `GET /agent-workspace/reports/:id/live-snapshot`。
- 使用 5-15 秒准实时轮询。
- 后续再按需要升级 SSE 或 WebSocket。
- 数据源只来自平台训练、评估、Notebook、CLI/MCP、Agent Bridge 的事实回流；Agent 只做解释、归因、风险判断和报告组织，不补造指标数据点。

### 4.5 数据报告详情

定位：数据处理、数据对比、数据适用性分析的证据页。

页面模块：

- 详情头部：名称、类型、创建人、生成时间、来源渠道、引用报告。
- 主要结论：本次数据处理或分析产生的结论。
- 适用目标：适合哪个训练/评估/实验目标。
- 数据变化：处理前后样本数、重复率、异常样本、分布变化、版本差异。
- 问题与建议：数据偏差、负迁移风险、补充数据建议。
- 样本证据：少量代表样本和跳转数据服务的入口。
- 引用关系：被哪些实验报告引用。

设计边界：

- 完整样本、字段、版本管理仍回到数据服务。
- 本页只承接本次目标型数据分析的结论和证据。

### 4.6 实验对比详情

定位：多训练、多评估、多版本、多数据之间的结构化对比证据页。

P0 必须有的可视化：

- 核心指标柱状图。
- 训练或评估曲线折线图。
- 能力维度涨跌图。
- 对比对象矩阵。

页面模块：

- 详情头部：对比名称、对比类型、创建人、生成时间、来源渠道。
- 推荐结论：推荐对象、关键原因、风险说明。
- 指标图表：柱状图、折线图、能力涨跌图。
- 对比矩阵：对象、数据集、参数、训练指标、评估指标、产物状态、Agent 结论。
- 参数/数据 diff：默认折叠，按需展开。
- 引用关系：被哪些实验报告引用。

设计边界：

- 图表用于快速判断趋势，表格用于追溯细节。
- 对比对象超过 4 个时，默认展示关键字段，次级字段折叠。
- Agent 结论必须有证据入口。

### 4.7 实验日志详情

定位：日志原文、异常片段、来源和采集方式的追溯资产。

页面模块：

- 详情头部：日志名称、来源、创建人、采集时间、关联对象。
- 日志结论：关键报错、风险、修复建议。
- 完整日志查看器：支持行号、异常高亮、复制、折叠。
- 时间线：关键事件、错误发生时间、重试与修复记录。
- 来源追溯：任务、Notebook/SSH/IDE/CLI 会话、文件路径、采集方式。
- 引用关系：被哪些实验报告引用。

设计边界：

- 日志分析结论进入实验报告正文。
- 本页负责完整日志、异常片段和来源追溯。

### 4.8 SkillHub

定位：Agent 可调用能力库，展示系统能力包和我的能力包。

Tab：

- 系统能力包。
- 我的 Skill。

系统能力包首版：

| 能力包 | 用户理解 | 主要产物 |
| --- | --- | --- |
| 报告生成 | 组织目标、证据、结论、风险和下一步。 | 实验报告、报告更新、变更记录、可靠性状态。 |
| 实验对比 | 对比训练、评估、版本、数据和指标。 | 实验对比详情、对比摘要、推荐对象。 |
| 数据分析 | 分析数据变化、适用性和风险。 | 数据报告详情、数据变化、适用性结论。 |
| 日志与报错诊断 | 识别异常片段、解释报错、给出修复建议。 | 实验日志详情、诊断结论、修复建议。 |
| 代码与参数检查 | 检查配置、参数 diff、代码版本和复现风险。 | 参数风险、可复现性证据。 |
| 深度实验分析 | 做数据贡献、超参敏感性、成本收益等深度判断。 | 深度分析模块、下一步建议。 |
| 知识沉淀与交付 | 整理周报、复盘、交付材料和研究叙事。 | 交付版报告、复盘材料。 |

我的 Skill：

- 支持导入 `SKILL.md + references/scripts/assets`。
- 支持编辑、预览、发布、禁用、删除。
- 编辑中版本不被 Agent 调用，发布后才可调用。
- 脚本执行受权限、安全策略、用户确认和执行记录约束。

### 4.9 MCP 与系统接入边界

MCP 页面 Tab：

- 系统 MCP。
- 我的 MCP。

系统 MCP 展示：

- 平台能力连接状态。
- 覆盖能力组：项目、数据、训练、评估、Notebook、实验档案、SkillHub、MCP。
- 权限说明、最近调用状态、异常提示。

我的 MCP 展示：

- 连接名称。
- 状态：未配置、已连接、异常、权限失效、已禁用。
- 用途。
- 权限范围。
- 最近检查时间。
- 操作：配置、测试连接、重新授权、禁用、删除。

设计边界：

- Lab CLI、Lab MCP Server、Context Pack 属于系统设计与开发文档内容，不作为普通用户产品页面中的显性模块展示。
- 产品界面只展示用户可理解、可管理的 MCP 连接、授权范围和状态。
- 系统接入不能绕过账号权限、项目权限、确认机制和审计边界。
- 外部工作流生成或更新报告后，用户只感知为对话结果卡片、实验报告或证据资产更新。

## 五、状态、权限、版本与证据规则

### 5.1 可靠性状态

| 状态 | 使用场景 | 展示要求 |
| --- | --- | --- |
| 可信 | 证据完整、对象可追溯、结论稳定。 | 状态标签 + 关键证据摘要。 |
| 有风险 | 数据、参数、日志或对比存在明确风险。 | 状态标签 + 风险原因 + 补证入口。 |
| 证据不足 | 缺关键日志、结果、对象或上下文。 | 状态标签 + 缺失证据清单。 |
| 人工修订 | 用户手动编辑形成新版本。 | 状态标签 + 修订人 + 修订时间。 |
| 生成失败 | 生成过程失败或权限不足。 | 错误原因 + 重试入口。 |

`证据不足` 也是正式报告状态，不使用草稿概念。

### 5.2 线性版本

| 场景 | 版本规则 |
| --- | --- |
| 同一目标普通追加 | 更新当前报告，不一定新增版本，但必须提醒用户。 |
| 补充证据并重新生成 | 新增 V2/V3 等线性版本。 |
| 用户编辑已形成结论内容 | 新增版本，保留修订记录。 |
| 目标发生变化 | 新建报告，不在旧报告上新增版本。 |
| 导出 Markdown/PDF | 不新增版本，导出内容记录当前版本号和导出时间。 |

### 5.3 撤回与纠正归属

- 报告生成或更新后，对话中的结果附件必须提供撤回本次追加。
- 撤回只移除本次追加到报告的内容，不删除底层任务、数据、日志、Skill/MCP 调用记录。
- 如果目标归属不确定，Agent 应展示候选报告与新建报告选择。
- 归属纠正必须留下必要记录，便于后续追溯。

### 5.4 Agent 平台动作确认

适用动作：

- 创建训练任务。
- 创建评估任务。
- 部署模型。
- 停止任务。
- 释放资源。
- 重启任务。
- 写回数据集版本。

确认面板字段：

- Agent 理解的动作。
- 将影响的对象。
- 执行后的变化。
- 权限与风险。
- 取消 / 确认执行。

强确认动作：

- 删除底层数据。
- 删除模型产物。
- 覆盖版本。
- 公开发布。
- 对外分享。
- 敏感数据导出。

### 5.5 权限与导出

- Agent、Skill、MCP、CLI/MCP 调用均不能绕过账号和项目权限。
- 权限不足时隐藏敏感字段，并给出可理解的原因。
- 导出 Markdown/PDF 受权限控制。
- 首版不做公开链接、对外分享、复制公开链接。
- 平台审计记录不进入实验档案主导航。

## 六、视觉与交互规范

### 6.1 视觉方向

目标气质：精确、可信、工程化。

视觉策略：

- 浅色企业研发工作台。
- 克制主色，延续科技蓝，但避免大面积蓝紫渐变。
- 中高信息密度，表格、状态条、分组、证据引用优先。
- 报告正文以连续阅读为主，少用嵌套卡片。
- Agent 可见但不喧宾夺主。

避免：

- 通用 AI 聊天机器人视觉。
- 营销型 Hero。
- 紫色光效和装饰性背景。
- 每个模块都做大卡片。
- 把内部 Skill 调用过程直接暴露给普通用户。

### 6.2 组件词汇

| 组件 | 用途 | 设计要求 |
| --- | --- | --- |
| 顶部状态条 | 报告可靠性、版本、创建人、来源 | 紧凑、可扫描、文字与颜色同时表达状态。 |
| 资产列表 | 报告、数据报告、对比、日志 | 表格优先，支持筛选、排序、搜索。 |
| 正文模块 | 报告正文 | 连续阅读，层级清晰，不做左右割裂。 |
| 证据导航 | 跳转详情资产与业务对象 | 摘要 + 状态 + 引用关系。 |
| 图表区 | 实验对比、数据变化 | 图表说明趋势，表格负责追溯。 |
| 日志查看器 | 完整日志和异常片段 | 行号、异常高亮、复制、折叠。 |
| Agent 抽屉 | 当前上下文追问和动作确认 | 默认收起，展开后不破坏主阅读路径。 |
| 结果卡片 | 生成、更新、撤回反馈 | 短摘要 + 明确操作。 |
| 确认面板 | 高影响动作确认 | 动作、对象、变化、风险都要清楚。 |

### 6.3 响应式与可访问性

- 桌面工作台优先。
- 窄屏下左侧导航和 Agent 抽屉转为覆盖式。
- 表格支持横向滚动或关键字段折叠。
- 状态不只依赖颜色，必须有文字标签。
- 长中文、英文路径、技术名词必须可换行或折叠。
- 抽屉、确认面板、Tab、筛选、表格操作支持键盘操作。

## 七、原型评审路径

正式原型按以下路径评审：

1. 打开 1.0 平台基础页，确认壳层贴近当前产品截图，且只有右上角 `Lab Agent` 一个入口。
2. 点击右上角 `Lab Agent`，进入 Lab Agent Workspace 新对话。
3. 确认新对话是空白输入态，且对话会被保存到左侧列表。
4. 点击左侧某条已保存对话，查看常规消息流、报告生成结果附件、撤回入口。
5. 进入实验报告列表，确认列表字段、筛选和目标型命名。
6. 打开进行中的实验报告详情，确认实时指标走势、当前进度、预计进度、ETA、阶段时间线和关键风险。
7. 打开已生成的实验报告详情，确认正式文档阅读、原始需求、变更记录、可靠性状态和证据导航。
8. 从报告跳转数据报告详情，确认数据变化和适用性证据。
9. 从报告跳转实验对比详情，确认柱状图、折线图、能力涨跌图和矩阵。
10. 从报告跳转实验日志详情，确认完整日志、异常片段和来源追溯。
11. 查看 SkillHub，确认只展示系统能力包和我的 Skill，不展示内部编排过程。
12. 查看 MCP，确认只展示系统 MCP、我的 MCP、连接状态和授权范围，不展示 CLI 命令或内部协议。
13. 点击右上角图标式展开按钮，确认右侧对话默认收起、带入上下文、追问不自动写回报告。

## 八、阶段验收标准

### 8.1 P0 设计验收

- 1.0 平台入口、Workspace、实验档案、报告详情和证据资产形成完整主闭环。
- 左侧不展开具体报告，列表在主内容区展示。
- 新对话页是输入框优先的空白输入态，对话线程保存在左侧对话列表。
- 实验报告按目标命名，不按能力命名。
- 报告详情包含原始需求、变更记录、结论、路径、证据、风险、下一步。
- 进行中报告详情包含实时指标走势、当前进度、预计进度、ETA、阶段时间线、最近事件和关键风险。
- 数据报告、实验对比、实验日志是证据资产，不替代平台业务模块。
- 实验对比详情包含柱状图、折线图、能力涨跌图。
- 实验日志详情能展示完整日志和来源追溯。
- SkillHub 展示系统能力包，不平铺内部 Skills。
- MCP 页面只展示用户可理解的连接状态和授权范围，不展示 CLI、Context Pack 等系统中间产物。

### 8.2 P1/P2 后续设计验收

- 我的 Skill 支持导入、编辑、发布、禁用和版本查看。
- 我的 MCP 支持新增、编辑、禁用、删除和重新授权。
- 结构化配置草案复用平台原表单字段和校验。
- 项目级 Skill/MCP、协作评审、对外分享、完整审计中心均作为后续设计，不进入首版主闭环。

## 九、风险与后续开发关注

| 风险 | 说明 | 后续处理 |
| --- | --- | --- |
| 报告归属误判 | 同一目标追加到错误报告会影响信任。 | P0 必须支持撤回和归属纠正。 |
| 证据链过重 | 报告若堆太多细节会难读。 | 摘要在报告，明细进证据资产。 |
| SkillHub 复杂度外露 | 平铺内部 Skills 或展示内部编排会让用户误解为配置中心。 | 只展示能力包、用途、状态和权限范围。 |
| 外部工作流绕权 | CLI/MCP 等系统接入如果边界不清会有安全风险。 | 必须绑定账号权限、确认机制和审计。 |
| 原型被误认为开发完成 | HTML 原型只验证信息架构和交互。 | 后续必须另出开发方案、数据模型和接口边界。 |

本方案确认后，下一阶段应输出前后端开发方案，重点补齐实验档案数据模型、报告版本模型、可靠性检查、Skill/MCP 调用边界与现有业务模块接口。
