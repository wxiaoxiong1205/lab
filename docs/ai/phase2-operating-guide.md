# 第二阶段 AI Coding 总指南

## 1. 阶段目标

第二阶段的目标不是继续“按生产环境复刻”，而是：

- 以当前仓库为新基线
- 根据用户后续每一轮截图、草图、原型和文字需求持续迭代
- 稳定完成页面改版、信息架构调整、功能扩展、权限与状态调整
- 保持项目可运行、可构建、可部署

## 2. 默认真相源

默认优先级：

1. 用户当前明确需求
2. 用户提供的截图 / 原型 / 草图 / 交互说明
3. 当前仓库已验收代码
4. 第二阶段 AI 模板与指南
5. 第一阶段历史文档

只有用户明确要求时，才重新参考生产环境。

## 3. 推荐工作流

### 3.1 每轮开始
- 阅读 `AGENTS.md`
- 阅读和本轮需求直接相关的代码
- 阅读 `docs/ai/production-review-template.md`
- 如果涉及页面，阅读或更新 `pageDocs.ts` 对应文档

### 3.2 需求理解
- 拆解当前需求目标
- 拆截图与交互
- 判断影响范围
- 列出本轮不处理项

### 3.3 开发实施
- 先改壳层 / 路由 / 状态，再改页面细节
- 先改结构，再改视觉
- 先改共享逻辑，再改散落页面

### 3.4 收尾
- 更新页面右侧设计文档
- 运行构建
- 输出风险点和下一步建议

## 4. 后续 AI 建议提示词骨架

可供后续 AI coding 直接沿用：

```md
请先阅读根目录 AGENTS.md，并阅读本轮需求相关代码与 docs/ai 模板。

当前项目已进入第二阶段，默认不要再按第一阶段“生产环境复刻”模式工作，除非我明确要求。

请基于以下信息开展本轮工作：
1. 我当前这轮明确需求
2. 我提供的截图 / 原型 / 文字说明
3. 当前仓库已验收代码

请先输出：
- 当前理解
- 影响范围
- 本轮实施方案
- 需要同步更新的页面内嵌设计文档

确认后直接进入开发，不要停留在空泛分析。
开发完成后请给出：
- 实际修改内容
- 自检结果
- 风险点
- 下一步建议
```

## 5. 第一阶段材料的处理方式

以下文件均为历史归档：

- `docs/ai/production-review-round1.md`
- `docs/ai/module-delivery-data-service-round*.md`
- `docs/ai/next-phase-module-plan.md`
- 历史探索报告、历史生产环境截图

使用规则：

- 可以查阅
- 不作为默认执行依据
- 若引用，必须明确说明“历史背景”

## 6. 页面内嵌设计文档要求

- 每次页面改动都要检查右侧设计文档
- 新增页面必须补设计文档
- 信息架构变化要写明“旧结构 -> 新结构”
- 截图驱动改版要在文档里记录关键布局变化

## 7. 第二阶段的质量门槛

每轮至少满足：

- 页面可访问
- 路由正确
- 交互符合当前需求
- 页面文档同步
- `npm run build` 通过

如果做不到，必须在输出中明确说明阻塞点。
