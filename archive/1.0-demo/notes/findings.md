# 数据权限升级发现记录

## 2026-05-22 初始盘点

- 当前权限核心在 `fastdata-llm-training/src/services/permissionStore.ts` 和 `fastdata-llm-training/src/services/permissionCatalog.ts`。
- 现有 `RoleKey` 是固定 union：`platform_admin | project_admin | training_engineer`，不支持自定义角色。
- 当前项目成员里有 `hasDataPermission`，但它实际用于“是否有项目访问权限”，不是新需求中的“个人数据 / 全部数据”。
- 当前权限配置页 `PermissionConfig.tsx` 只有操作权限 tab，内置角色操作权限只读，没有新增/编辑角色能力。
- 当前项目管理创建/编辑页仍有“项目管理员”字段，需要移除；成员管理已展示角色，但不能在添加成员时选择角色。
- 当前资源删除权限有 `resourceReferenceGuard.getCreatorDeletePermission`，但只覆盖删除，且把项目管理员/租户管理员硬编码为可删；新需求需要按数据权限统一控制详情、编辑、删除、启动、下载等操作。
- 数据服务资源大多有 `creator`；Notebook 有 `creatorAccount`；机器学习和服务页有些 mock 用 `admin/lab1/deepexilab`，需要统一账号映射。

## 用户确认口径

- 列表展示基础行信息，搜索可命中其他人的数据。
- 无全部数据权限时，只能操作自己的数据；操作其他人的数据提示权限不足。
- 系统管理中凡涉及人创建的数据也需要控制。
- 租户管理员隐藏，不在权限配置和项目成员添加中体现，但登录态默认全权限。
- 内置三个可见角色不可编辑，自定义角色需要完整闭环。
- 项目成员添加时需要选择角色，且只能选该用户被控制台赋予的角色。

## 实现记录

- `permissionStore` 已改为动态角色 key，保留隐藏的 `platform_admin` 作为租户管理员。
- 角色增加 `dataPermissions`，覆盖 `llm`、`machine`、`system` 三个域；个人数据/任务隐式拥有，`all=true` 表示全部数据。
- 项目成员从旧的 `hasDataPermission` 布尔值迁移为“成员存在即有项目访问权限”，项目内角色由 `roleKey` 决定。
- 权限配置页新增数据权限 tab、新建/编辑/删除自定义角色、用户角色授权弹窗。
- 项目管理页删除项目管理员字段，成员添加时必须选择用户和该用户已授权角色。
- 资源数据权限 helper 已接入训练/测试数据、推理结果集、机器学习数据/标注、Notebook、在线推理服务、在线标注服务、大模型模型、机器学习部署等高频入口。
- 页面内嵌文档已同步项目管理和权限配置的新口径。

## 2026-05-22 二次扫尾

- 发现多个页面已经拦截了操作按钮，但行内名称/描述编辑仍可进入编辑态或保存：数据标注、数据清洗、评估任务、部署服务、在线推理服务、模型管理、机器学习标注、机器学习模型管理、机器学习部署、在线标注服务。
- 已给通用 `TaskMetadataEditor` 增加只读能力，并在上述页面按数据权限禁用编辑入口；保存时仍会二次校验，避免 DOM 直触发绕过。
- 发现部分直达路由可绕过列表按钮限制：大模型/机器学习 Notebook 详情、编辑、发布案例；评估报告、人工评估；训练任务详情、训练版本详情；机器学习在线标注工作台。
- 已补直达路由 403/权限不足拦截，保持“列表可见可搜索，但详情和操作不可用”的用户确认口径。
- 发现部分新建资源 creator 仍硬编码为 `deepexilab` 或 `zhangsan`：标注任务、清洗任务、评估任务、部署服务、在线推理服务、机器学习模型、机器学习部署。
- 已改为从 `getCurrentUser()` 写入当前账号，降低后续“个人数据/任务”演示不稳定风险。

## 2026-05-22 三次扫尾

- 通过脚本扫描所有 `TaskMetadataEditor` 使用点，发现训练/验证数据集、测试数据集、推理结果集、大小模型 Notebook 列表仍有名称/描述行内编辑缺少 `disabled`。
- 已补齐上述入口的数据权限禁用和保存时二次校验，防止“列表可见但不能操作”的规则被行内编辑绕过。
- 推理结果集明细单条删除也补了数据权限校验；无权限时提示权限不足，不再弹出删除确认。
- 测试数据集版本类型补充 `creator?: string`，使版本描述编辑可以按版本创建人做权限兜底。
