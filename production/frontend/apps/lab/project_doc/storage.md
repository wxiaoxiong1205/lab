# 存储服务管理系统

## 1. 概述

存储服务管理系统是Dataset Management System的核心基础设施模块，负责管理多种类型的存储服务配置，并支持与Kubernetes集群的映射关系。系统基于JuiceFS文件系统，提供统一的存储接口，支持企业级的数据存储、备份和分布式访问需求。

### 1.1 系统目标

- **统一存储管理**：支持多种存储类型的统一配置和管理
- **集群存储映射**：一个存储服务可以映射到多个Kubernetes集群使用
- **动态配置**：支持存储配置的动态创建、更新和删除
- **连接测试**：提供存储服务的连通性验证功能
- **安全管理**：敏感信息的加密存储和脱敏显示

## 2. 支持的存储类型

### 2.1 火山引擎 TOS (Volcano Engine Object Storage)
基于火山引擎提供的对象存储服务，适用于生产环境的大规模数据存储。

**配置参数**：
- `endpoint`: TOS完整服务端点地址（如：https://my-bucket.tos-s3-cn-beijing.volces.com）
- `access_key`: 访问密钥ID
- `secret_key`: 访问密钥Secret（敏感信息）

**JuiceFS命令格式**：
```bash
juicefs format --storage tos --bucket {endpoint} --access-key {access_key} --secret-key {secret_key} [filesystem_name]
```

### 2.2 MinIO
开源的对象存储服务，适用于私有云和混合云环境。

**配置参数**：
- `endpoint`: MinIO完整服务端点（如：http://127.0.0.1:9000/my-bucket）
- `access_key`: 访问密钥
- `secret_key`: 密钥（敏感信息）

**JuiceFS命令格式**：
```bash
juicefs format --storage minio --bucket {endpoint} --access-key {access_key} --secret-key {secret_key} [filesystem_name]
```

### 2.3 NFS (Network File System)
网络文件系统，适用于本地网络环境的文件共享。

**配置参数**：
- `host`: NFS服务器地址

**JuiceFS命令格式**：
```bash
juicefs format --storage nfs --bucket {host} [filesystem_name]
```

## 3. 核心功能需求

### 3.1 存储配置管理

#### 3.1.1 配置CRUD操作
- **创建配置**：支持三种存储类型的配置创建，包含参数验证
- **查询配置**：支持列表查询、详情查询、分页和筛选
- **更新配置**：支持配置信息的修改和参数更新
- **删除配置**：安全删除配置，需确认映射关系

#### 3.1.2 配置验证
- **参数验证**：根据存储类型验证必需参数的完整性
- **格式验证**：验证endpoint、路径等参数的格式正确性
- **连接测试**：提供存储服务的连通性测试功能
- **状态管理**：记录连接测试结果和时间戳

#### 3.1.3 配置管理简化
- **配置平等性**：所有存储配置具有同等地位，不设置默认配置
- **简化使用**：用户根据实际需要选择合适的存储配置
- **灵活选择**：支持在不同场景下使用不同的存储配置

#### 3.1.4 安全管理
- **敏感信息加密**：secret_key等敏感字段的加密存储
- **脱敏显示**：前端显示时对敏感信息进行脱敏处理
- **权限控制**：仅管理员可进行存储配置管理

### 3.2 存储与集群绑定管理（2024年优化）

#### 3.2.1 绑定关系设计
- **一对多绑定**：一个存储配置可以绑定到多个Kubernetes集群
- **关系管理**：支持绑定关系的创建、查询、批量更新操作
- **状态同步**：绑定关系变更时同步到相关集群

- **Transfer组件**：采用直观的左右选择界面，参考镜像仓库绑定设计
- **批量操作**：支持一次性绑定/解绑多个集群，提升操作效率
- **集群状态过滤**：自动排除离线或错误状态的集群，确保绑定有效性
- **搜索功能**：支持按集群名称搜索，快速定位目标集群
- **实时预览**：显示将要绑定的集群数量，操作前可预览结果

#### 3.2.3 绑定界面优化
- **状态可视化**：用颜色标签区分集群状态（在线/离线/错误）
- **详细信息**：显示集群API地址、版本信息、节点数量等
- **交互优化**：简化操作流程，减少用户学习成本
- **错误处理**：提供详细的错误信息和解决建议

#### 3.2.4 集群存储配置
- **存储服务配置**：在集群管理中配置关联的存储服务，而非传统存储类
- **服务映射管理**：支持添加/移除集群与存储服务的映射关系
- **动态挂载**：支持根据映射关系动态挂载存储
- **资源隔离**：确保不同项目间的存储资源隔离

### 3.3 JuiceFS集成

#### 3.3.1 配置转换
- **命令生成**：根据存储配置自动生成JuiceFS format命令

## 4. 数据模型设计

### 4.1 存储配置表 (storage_configs)

```sql
CREATE TABLE storage_configs (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL UNIQUE,
    description TEXT,
    storage_type ENUM('tos', 'minio', 'nfs') NOT NULL,
    config_data JSON NOT NULL,
    last_test_at DATETIME,
    test_status ENUM('success', 'failed', 'untested') DEFAULT 'untested',
    test_message TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    INDEX idx_storage_type (storage_type)
);
```

**注意**: 已简化存储配置管理，移除了启用/禁用状态控制和默认配置功能，所有存储配置均为可用状态且具有同等地位，通过连接测试来验证配置有效性。

### 4.2 存储集群映射表 (storage_cluster_mappings)

```sql
CREATE TABLE storage_cluster_mappings (
    id INT PRIMARY KEY AUTO_INCREMENT,
    storage_config_id INT NOT NULL,
    cluster_id VARCHAR(100) NOT NULL,
    mount_path VARCHAR(255),        -- 已简化：前端不再使用此字段
    filesystem_name VARCHAR(100),   -- 已简化：前端不再使用此字段
    mount_options JSON,             -- 已简化：前端不再使用此字段
    is_active BOOLEAN DEFAULT TRUE, -- 已简化：前端不再显示和管理此状态
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    FOREIGN KEY (storage_config_id) REFERENCES storage_configs(id) ON DELETE CASCADE,
    UNIQUE KEY uk_storage_cluster (storage_config_id, cluster_id),
    INDEX idx_storage_mapping_config (storage_config_id),
    INDEX idx_storage_mapping_cluster (cluster_id)
);
```

**注意**: 
- 为了简化用户体验，前端界面已移除对 mount_path、filesystem_name 和 mount_options 字段的配置和显示。
- 已简化集群映射状态管理，前端不再显示和操作 is_active 状态，所有映射关系均为有效状态。

## 7. 业务流程

### 7.1 存储配置创建流程

1. **选择存储类型**：用户选择TOS、MinIO或NFS
2. **填写配置参数**：根据存储类型填写相应参数
3. **参数验证**：系统验证参数格式和完整性
4. **连接测试**：可选的连接测试验证配置有效性
5. **保存配置**：保存配置并设置初始状态
6. **集群映射**：选择要映射的Kubernetes集群

### 7.2 集群存储映射流程

1. **选择存储配置**：从可用存储配置中选择
2. **配置映射参数**：设置挂载路径、文件系统名等
3. **验证权限**：验证集群访问权限和存储权限
4. **创建映射关系**：在数据库中创建映射记录
5. **同步配置**：将存储配置同步到目标集群

### 7.3 JuiceFS文件系统创建流程

1. **读取存储配置**：获取存储服务配置参数
2. **生成JuiceFS命令**：根据存储类型生成format命令
3. **文件系统初始化**：执行JuiceFS format命令
4. **挂载点配置**：在集群中配置挂载点
5. **状态更新**：更新文件系统状态和映射状态
