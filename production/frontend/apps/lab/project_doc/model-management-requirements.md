# 模型管理需求文档

## 项目背景
模型管理是AI/ML平台的核心功能模块，旨在为数据科学家和ML工程师提供统一的模型生命周期管理能力。该模块整合了来自不同来源的AI模型（实验产生、微调训练、预置模型等），提供统一的管理界面和操作入口。

## 核心愿景
构建一个类似MLflow风格的专业模型管理平台，支持模型的全生命周期管理，包括模型注册、版本控制、状态管理、性能监控和部署使用，为AI团队提供高效的模型资产管理解决方案。

## 主要目标

### 1. 统一模型管理
- **多来源集成**：整合来自实验、微调、上传、预置等不同来源的模型
- **统一界面**：提供一致的管理界面和操作体验
- **版本控制**：支持模型版本管理和变更追踪
- **状态管理**：支持模型生命周期状态管理

### 2. 简化用户体验
- **核心功能聚焦**：专注于模型的基本管理功能（创建、查看、编辑、删除）
- **界面简洁**：采用表格式布局，专业清晰
- **操作便捷**：减少复杂配置，突出核心属性
- **快速访问**：提供便捷的模型使用入口

### 3. 专业化管理
- **表格式展示**：参考MLflow界面风格，提供专业的表格管理界面
- **标签系统**：支持灵活的标签管理和分类
- **搜索筛选**：强大的搜索和排序功能
- **批量操作**：支持批量模型管理操作

## 详细功能需求

### 1. 模型列表管理

#### 1.1 界面设计要求
- **布局风格**：采用表格式布局，参考MLflow Model Registry界面
- **页面结构**：标题区域 + 搜索筛选区域 + 标签页 + 表格展示区域
- **响应式设计**：支持不同屏幕尺寸的自适应显示
- **现代化UI**：使用Ant Design组件，保持界面一致性

#### 1.2 表格列设计
| 列名 | 宽度 | 说明 | 必需 |
|------|------|------|------|
| 模型信息 | 300px | 名称、描述展示 | ✅ |
| 标签 | 200px | 最多显示3个标签 | ✅ |
| 更新时间 | 150px | 相对时间显示 | ✅ |
| 操作 | 120px | 查看、编辑、删除 | ✅ |

#### 1.3 搜索筛选功能
- **搜索框**：支持按模型名称和描述进行模糊搜索
- **排序选择**：支持按更新时间、创建时间、名称排序
- **排序方向**：支持升序和降序排列
- **实时搜索**：支持输入实时搜索和清空重置

#### 1.4 标签页分类
- **我的模型**：显示当前项目下的所有模型
- **公开模型**：显示公开共享的模型（预留功能）
- **标签页计数**：暂不显示数量统计

#### 1.5 分页功能
- **分页大小**：默认10条/页，支持10/20/50/100选项
- **分页控件**：使用Ant Design Pagination组件
- **总数显示**：显示总记录数量
- **页面保持**：搜索和筛选时保持分页状态

### 2. 模型详情管理

#### 2.1 页面布局
- **页面头部**：返回按钮 + 模型名称 + 操作按钮（使用模型、下载、分享）
- **基本信息区域**：模型基本属性展示
- **版本历史区域**：模型版本管理表格
- **简化设计**：移除统计概览，专注于版本管理

#### 2.2 基本信息展示
- **模型名称**：显示名称，支持显示名称和内部名称
- **描述信息**：多行文本描述
- **标签系统**：支持多标签展示和管理
- **创建信息**：创建者、创建时间、最后更新时间
- **状态信息**：当前状态标签展示

#### 2.3 版本历史管理
- **版本列表**：表格形式展示所有版本
- **版本信息**：版本号、状态、创建时间、大小、说明
- **版本操作**：查看详情、设为当前版本、下载、删除
- **状态标识**：不同状态的标签和图标展示

#### 2.4 模型使用集成
- **智能跳转**：根据模型类别自动跳转到对应使用场景
- **实验集成**：文本处理类模型跳转到实验管理
- **微调集成**：其他类型模型跳转到微调任务
- **状态传递**：传递模型信息到目标页面

### 3. 模型创建和编辑

#### 3.1 创建模型表单
- **简化设计**：只保留核心字段，降低用户操作复杂度
- **必填字段**：模型名称（string，必填）
- **可选字段**：描述（textarea，可选）、标签（tags，可选）
- **表单验证**：名称唯一性验证、长度限制验证
- **友好提示**：提供输入示例和操作指导

#### 3.2 编辑模型表单
- **一致性设计**：与创建表单保持完全一致
- **数据回填**：编辑时自动填充现有数据
- **增量保存**：只更新修改的字段
- **操作确认**：关键操作提供确认提示

#### 3.3 表单交互设计
- **模态框形式**：使用Modal组件，避免页面跳转
- **表单布局**：垂直布局，标签上置
- **操作按钮**：取消、保存按钮，右对齐排列
- **加载状态**：提交时显示加载状态
- **错误处理**：完善的错误提示和处理

#### 3.4 字段设计规范

```typescript
// 模型版本信息
interface ModelVersion {
```

### 5. API接口规范

#### 5.1 模型管理接口
```typescript
// 获取模型列表
GET /api/v1/models/by-project/{project_id}/
Parameters:
  - page: number (页码，默认1)
  - page_size: number (页面大小，默认10)
  - search?: string (搜索关键词)
  - sort_by?: string (排序字段)
  - sort_order?: 'asc' | 'desc' (排序方向)

// 获取模型详情
GET /api/v1/models/{model_id}/

// 创建模型
POST /api/v1/models/by-project/{project_id}/
Body: CreateModelRequest

// 更新模型
PUT /api/v1/models/{model_id}/
Body: UpdateModelRequest

// 删除模型
DELETE /api/v1/models/{model_id}/
```

#### 5.2 版本管理接口
```typescript
// 获取模型版本列表
GET /api/v1/models/{model_id}/versions/

// 创建新版本
POST /api/v1/models/{model_id}/versions/
Body: CreateVersionRequest

// 设置当前版本
PUT /api/v1/models/{model_id}/versions/{version_id}/set-current

// 删除版本
DELETE /api/v1/models/{model_id}/versions/{version_id}/
```

### 6. 用户流程设计

#### 6.1 模型浏览流程
1. **进入模型管理**：用户点击菜单中的"模型管理"
2. **查看模型列表**：显示项目下所有模型的表格列表
3. **搜索筛选**：用户可通过搜索框查找特定模型
4. **排序查看**：支持按不同字段排序查看
5. **切换分类**：在"我的模型"和"公开模型"间切换

#### 6.2 模型创建流程
1. **点击创建**：用户点击"创建模型"按钮
2. **填写信息**：在弹出的表单中填写模型基本信息
3. **提交创建**：点击保存按钮创建模型
4. **创建成功**：显示成功提示，刷新列表
5. **查看结果**：新创建的模型出现在列表中

#### 6.3 模型详情查看流程
1. **点击查看**：用户点击模型行的"查看"按钮
2. **进入详情**：跳转到模型详情页面
3. **查看信息**：浏览模型基本信息和版本历史
4. **版本管理**：查看和管理模型的不同版本
5. **使用模型**：点击"使用模型"跳转到应用场景

#### 6.4 模型编辑流程
1. **点击编辑**：用户点击操作列的"编辑"按钮
2. **修改信息**：在弹出的表单中修改模型信息
3. **保存更改**：点击保存按钮提交修改
4. **更新成功**：显示成功提示，更新列表显示
5. **查看更改**：确认修改内容已生效
