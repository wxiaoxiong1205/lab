## 适用场景

- 新增功能、改动范围较大、涉及 DB/接口协议/任务/K8s/存储/权限的改动

## 强制流程（不满足则先补齐再写代码）

1. **需求分析**：把“真实问题、价值、边界、影响面、验收标准”写清楚
2. **需求设计**：把“功能结构、主/异常流程、数据输入输出、权限与状态流转”写清楚
3. **技术方案**：明确技术落点与风险（可直接使用本规则下方的最小模板）

## 技术方案最小模板（AI 输出时至少包含）

- **需求描述**：功能概述、使用场景、预期效果、边界条件
- **技术方案**：
  - 数据库设计（如涉及）：表/字段/索引/兼容策略；结构变更如何交付 SQL（运维执行）
  - API 设计：新增/修改接口、请求响应结构、错误码/状态码
  - 业务流程：分层调用链（API→Service→Repository→DB/外部系统）
  - 涉及文件清单：新增/修改的文件路径
  - 依赖关系：K8s/Redis/存储/外部 HTTP 等
- **风险评估**：技术/业务/性能风险与应对
- **测试计划**：单测/集成/回归
