## PR/MR 描述（强制）

- **必须写清**：
  - 背景/问题：为什么要改
  - 方案摘要：分层落点（API/Service/Repository/Model/Schema/Task/Config）
  - 影响面：API/任务/配置/数据表/兼容性
  - 验证方式：如何复现/如何验证通过
  - 风险与回滚：失败场景、回滚步骤、是否需要运维配合

## 提交前自审清单（强制）

- **基础**：
  - [ ] 无调试代码（print/debugger）
  - [ ] 新增/修改函数有类型注解
  - [ ] 关键逻辑有必要的中文注释（不是逐行注释）
- **API**：
  - [ ] `response_model`/状态码正确；列表接口支持分页
  - [ ] 参数校验/错误返回与 `app/main.py` 一致
- **数据库/多租户**：
  - [ ] 不绕过 `tenant_id` 隔离；无 raw SQL 拼接
  - [ ] Model 继承 `baseModel`，字段 `comment` 完整
  - [ ] 不使用外键约束；索引在 `__table_args__`
- **任务**：
  - [ ] 幂等性/重试策略明确；资源释放正确
- **配置**：
  - [ ] 新增配置已更新 `app/core/config.py` + `env.example`
  - [ ] 业务代码未直接使用 `os.getenv`
- **表结构变更（运维执行）**：
  - [ ] 提供升级 SQL + 回滚 SQL + 验证 SQL + 执行说明
