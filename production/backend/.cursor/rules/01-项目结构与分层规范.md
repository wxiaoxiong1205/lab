## 目录与职责（以现有代码为准）

- **入口**：`app/main.py`（FastAPI app、middleware、路由注册、lifespan）
- **路由层**：`app/api/v1/`（只做编排，不做复杂业务）
- **业务层**：`app/services/`（核心业务逻辑、跨资源编排、调用仓储/外部系统）
- **数据访问层**：`app/repository/`（CRUD/查询构造/事务边界建议在此收敛）
- **模型**：`app/models/`（SQLAlchemy）
- **Schema**：`app/schemas/`（Pydantic v2，用于入参/出参）
- **任务**：`app/tasks/`（Celery 任务、后台周期性任务、消费者等）
- **配置**：`app/core/config.py`（强依赖环境变量；新增配置必须同步 `env.example`）
- **数据库**：`app/database/`（引擎/会话/多租户注入/方言适配等）
- **文档**：仓库内的接口/架构/结构文档需与代码同步（具体目录以当前仓库为准）

## 技术栈速记（用于定位问题/选型）

- **Web**：FastAPI
- **ORM**：SQLAlchemy 2.x（异步 + 同步）
- **DB**：MySQL / PostgreSQL / 达梦（DM）
- **任务**：Celery + Redis（含 Sentinel）
- **K8s**：`kubernetes` / `kubernetes_asyncio`
- **存储**：JuiceFS / MinIO / TOS
- **日志**：loguru + Loki/Alloy
- **实验跟踪**：MLflow

## 强制分层规则

- **API 层禁止**：
  - 直接写复杂业务逻辑（循环/状态机/多表事务/长流程）
  - 直接拼装 SQL（需要 SQL 时放到 `repository`）
- **Service 层必须**：
  - 明确输入/输出（优先用 `schemas`）
  - 封装跨资源流程（DB + 存储 + K8s + 外部 HTTP 等）
- **Repository 层必须**：
  - 只关注数据访问与查询表达
  - 明确租户语义（避免绕过 `tenant_id` 自动注入机制）

## 新增功能的推荐落点（模板）

- **新增一个 REST 接口**：
  - `app/api/v1/<模块>.py`：路由与依赖
  - `app/schemas/<模块>.py`：请求/响应 schema
  - `app/services/<模块>_service.py`：业务逻辑
  - `app/repository/<模块>_mapper.py`：数据访问（如需要）
- **新增一个后台任务（Celery）**：
  - `app/tasks/<领域>_tasks.py`：任务定义
  - `app/services/<领域>_service.py`：被任务调用的业务逻辑
