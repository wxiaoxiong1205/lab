# lab-coding

DeepexiLab 模型训练平台的还原、补全、页面文档融合与持续演进工作仓库。

本仓库不是一个单纯的前端原型仓库，而是一个以生产环境为基线、面向前后端一体化交付的产品工程工作区。目标是在现有代码、历史文档和生产环境基础上，持续将平台补全为可运行、可构建、可部署的网站系统。

## 核心原则

- 默认以生产环境为功能真相源
- 如果代码、PRD、RPD、历史文档与生产环境冲突，一律以生产环境为准
- 必须先拆解生产环境，再修正文档理解，再进入开发
- `模型训练 - 大模型训练` 模块为受保护模块，除非用户明确提出，否则不得修改
- 以下功能不属于标准产品范围，不应继续开发：业务测试数据集、业务推理结果集、文件管理、业务效果评估、API 服务
- 开发范围包括前端和后端，目标是最终可部署

产品范围说明：

- 数据管理、模型训练、模型评估是平台主线核心能力
- 模型服务、系统管理等标准平台模块同样属于必要范围
- 只有上面明确排除的模块，不需要开发或继续增强

## 页面内嵌需求说明

本项目后续采用“页面功能与设计文档融合”的方式推进。

目标交互：

- 页面右下角提供浮动按钮
- 点击后展开需求说明侧板
- 优先采用“推挤主内容区”的展开方式，而不是遮挡主内容
- 用户打开页面时，既能看功能效果，也能直接记录或查看当前页面需求说明
- 运行态需求说明默认保存在当前浏览器，不自动同步到仓库文件

这意味着：

- 页面不是只交付功能
- 页面也不是只交付说明文档
- 而是同时交付“功能界面 + 页面内可编辑需求说明”

## 关于后续功能新增或修改

在默认情况下，生产环境是基线。

但如果用户后续明确提出新增功能或修改功能，则该需求在其影响范围内高于当前生产环境，需要：

- 基于生产环境理解现状
- 基于用户需求定义未来态
- 同步修改代码实现
- 同步补充或修正 PRD / RPD 理解
- 如有需要，再调整页面中的运行态需求说明

也就是说：

- 生产环境决定“当前标准长什么样”
- 用户新增需求决定“接下来要演进成什么样”

## AI 协作文件

仓库中与 AI coding 配套的长期文件如下：

- [AGENTS.md](./AGENTS.md)
- [docs/ai/production-review-template.md](./docs/ai/production-review-template.md)

使用方式：

1. 开工前先阅读 `AGENTS.md`
2. 先按 `production-review-template.md` 输出生产环境拆解、差异分析和开发计划
3. 再按 `module-delivery-template.md` 逐模块开发、联调和自检
4. `page-design-doc-template.md` 仅作为 AI 工作流参考模板，不与页面中的运行态需求说明自动同步

## 启动前端工程

```bash
cd fastdata-llm-training
npm install
npm run dev
```

## UI 原型与截图复刻

如果后续工作涉及截图复刻、页面照图实现或原型还原，应优先使用已安装的 `protodesign` skill 或等效工作流，但仍需遵守以下原则：

- 功能以生产环境和用户明确需求为准
- 截图参考主要用于视觉与交互表达
- 如果截图中包含设计文档侧板，应把它视为页面结构的一部分
- 不得因照图实现而偏离真实业务逻辑
