# Product

## Register

product

## Users

DeepexiLab serves algorithm engineers, algorithm leads, evaluation/test users, delivery/project stakeholders, and platform administrators. They work across the platform, Notebook, SSH, IDE, CLI, and external Agent tools while handling model data, training, evaluation, deployment, diagnostics, comparison, and reporting.

## Product Purpose

DeepexiLab is an enterprise model研发 platform. The 2.0 Agent Native direction turns it into a model R&D workbench where Agent workflows can understand platform context, execute controlled actions, and preserve experiment reasoning assets without replacing the platform's native data, training, evaluation, and service modules.

Success means users can reliably ask Agent to analyze, diagnose, compare, summarize, and configure work; generated experiment reports become the default place to review target-driven work; external Notebook/SSH/IDE/Agent workflows can connect through authenticated CLI/MCP; and all high-impact actions remain governed by permission, confirmation, and audit.

## Brand Personality

Precise, trustworthy, engineering-native.

The product should feel like a serious enterprise AI engineering tool: calm, dense when necessary, explicit about evidence, and careful with permissions. It should avoid marketing theatrics, decorative Agent gimmicks, and casual chatbot patterns that undermine trust.

## Anti-references

- Generic AI chatbot side panels that ignore platform context.
- Decorative "AI purple glow" dashboards that look impressive but make operational work harder.
- Report centers detached from the real data, training, evaluation, and model objects.
- Plugin marketplaces that expose internal system mechanisms as user-editable tools.
- Over-carded layouts where every section floats in a card and hierarchy becomes unclear.

## Design Principles

1. **Evidence before ornament**: conclusions, reports, comparisons, and diagnostics must show enough evidence and source context to be trusted.
2. **Platform objects stay primary**: Agent surfaces reference data, training, evaluation, model, Notebook, and service objects without replacing their owning modules.
3. **Agent is visible but not intrusive**: Agent helps from the side, announces meaningful updates, and stays out of the way when the user is reading dense content.
4. **Governed extensibility**: SkillHub, MCP, CLI, and external Agents feel expandable, but every action has permission, confirmation, and audit boundaries.
5. **Reviewable by default**: reports, versions, updates, exports, and high-impact actions must be easy to inspect during product, design, engineering, and delivery review.

## Accessibility & Inclusion

Default target is WCAG AA for text contrast, focus visibility, keyboard operability, and non-color-only status communication. Product UI should support dense information without relying on tiny low-contrast text. Motion should communicate state changes only, with reduced-motion fallbacks. Long Chinese labels and mixed Chinese/English technical terms must fit within navigation, tables, buttons, and cards without truncation hiding critical meaning.
